2) timing and dynamic memory allocation of object declaration
    a) some objects need to be instantiated after Serial.begin() is called to ensure that the protocol works and does not crash the program
    b) there are two methods to solve this:
        i) heap allocation using the new keyword
             //mp = new MotionPlanner(g, duty_f, cycle_time, step_h);
             this is not preferable because memory used on the heap must bee freed by itself
        ii) static allocation of the object in setup (satisfying the timing and lifetime of the object) and a global pointer to the object
            MotionPlanner* mp = nullptr;
            void setup(){
                static MotionPlanner planner(g, duty_f, cycle_time, step_h); // statically stored for life of program
                mp = &planner; // connect pointer and static object
            }

    b) solution is to remove () -> static CommunicationManager comm;

    b) radio_interrupt is declared private: volatile static bool radio_interrupt;
        solution for this specific problem was radio_interrupt could only be accessed by a class-member function, whereas initially the static radioISR() converts

5) argument of type \"void (CommunicationManager::*)()\" is incompatible with parameter of type \"void (*)()\
    a) occurs when interrupt expects ISR to be global and not have an additional this, which occurs for non-static member functions
        void(*)(CommunicationManager*) is what the ISR received when the function was not static
        void(*)() is what the ISR received when static
        solution: static void radioISR() with handler function discussed above that can access the class object
            static functions cannot access members regardless of member visibility
